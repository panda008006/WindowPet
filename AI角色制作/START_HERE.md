# WindowPet 角色自动制作入口

这套流程面向能够读写本机文件并调用图片生成工具的 AI。用户只需提供角色参考图、名称和一句描述；AI 负责生成、拆帧、质检并安装。不要让用户手动裁剪、拆帧、写 JSON 或导入。

普通网页聊天没有本机文件权限，不能完成最后安装。此时应说明限制，不要声称已经写入软件。

## 动作模型

普通角色只自动使用三种基础状态：

| 动作 | 用户行为 | 规则 |
|---|---|---|
| `idle` | 默认待机 | 循环播放 |
| `click` | 左键单击 | 播放一次后回到待机 |
| `drag` | 左键拖动时 | 拖动期间循环，松开后回到待机 |

右键只打开功能菜单，不触发表演。角色的舞蹈、挥手、道具互动等额外动作，作为带名称的独立动画放在右键“动作”子菜单中；用户点选后播放一次并回到待机。悬停、双击、滚轮、中键、靠近屏幕边界、奖励和随机行为都不是动作触发方式。

身体不动、只让头部或眼神随鼠标方向变化的角色应使用专门的 `head_track` 5×5 网格格式，不混入上述三种基础动作。

## 必须按顺序执行

1. 完整阅读 `AI先读我.md`、`reference_image_mode.md`、`action_design_mode.md`、`质量标准.json`、`master_sheet_prompt.md` 和 `master_sheet_schema.json`。
2. 检查当前角色库地址和目录结构。不得删除、覆盖或改名任何已有角色。
3. 分析用户原图，锁定轮廓、头身比、脸型、五官、配色、纹理、线宽、服装、饰品和左右不对称细节。原图是唯一视觉真源。
4. 若角色可识别且有检索能力，查找 3–5 个有代表性的动作，只用于设计动作概念，不复制现成动画帧。
5. 为 `idle`、`click`、`drag` 分别写“预备—主动作—收势”分镜。额外动作按需单独规划，并给每个动作写用户能看懂的名称。
6. 使用当前已配置的图片生成 API 或账号，把参考图与 `master_sheet_prompt.md` 的最终提示词一起提交，生成固定 6 列 × 3 行、共 18 格的高分辨率主精灵图。WindowPet 不绑定具体模型或平台，也不要求重新配置账号。
7. 逐格目视检查：角色身份一致、动作真实、每格完整、没有文字或网格残留、没有只靠缩放或平移的伪动作。失败时重新生成主图，不要叠加图标补救。
8. 将主图保存到本地工作目录，不要放进已有角色目录。若本机 Python 缺少 Pillow，由 AI 执行：

   ```powershell
   python -m pip install -r "AI角色制作\requirements.txt"
   ```

   然后调用：

   ```powershell
   python "AI角色制作\build_character_from_sheet.py" `
     --sheet "<主精灵图绝对路径>" `
     --display-name "<角色显示名>" `
     --character-id "<英文角色名Pet>" `
     --assets-root "<当前用户的角色库绝对路径>" `
     --background auto
   ```

   生成器可靠输出透明背景时使用 `--background transparent`；纯色背景自动识别不理想时，传入实际颜色，例如 `--background "#12E8A0"`。
9. 工具会自动完成网格拆分、去纯色背景、18 帧共用裁剪窗口与缩放比例、输出 `192×208 RGBA PNG`、生成 `asset.json`、内置校验和同盘原子安装。同名角色存在时会拒绝覆盖。
10. 再运行：

    ```powershell
    python "AI角色制作\validate_character.py" "<实际角色目录>"
    ```

11. 确认 18 张 PNG 与三套独立基础动作均存在。额外动作应有独立文件夹和显示名称，例如：

    ```json
    "dance": { "folder": "dance", "fps": 10, "loop": false, "label": "跳个舞" }
    ```

私人角色默认只留在本机。除非用户主动要求公开，否则不要上传官网、云服务器或其他共享位置。

## 质量底线

- 18 格主精灵图的理想尺寸为 `3072×1536`（每格 `512×512`），最低建议 `2304×1152`（每格 `384×384`）。
- 生成器只能输出约 `1024×1024` 时，单格像素可能不足；先尝试高清模式，仍不足时改为分别制作动作行图或单独导入视频。
- 脚本只负责确定性拆分、清理和打包，不能把静态图变成真实动作，也不能修复角色身份漂移。
- 动作连贯性来自相邻帧真实姿势变化和一致的角色比例；禁止用整体放大、缩小、平移、旋转、透明度变化或抖动冒充动画。
